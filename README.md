# AgriPilot AI

**Team AgriNex.** "Smarter Decisions, Sustainable Agriculture."

An agricultural decision-support app for Pakistani farmers. Enter your farm, and it
returns a crop suitability analysis, an irrigation plan, climate risks, a financial
feasibility estimate, a what-if simulator and a downloadable PDF report.

## Run it locally

```bash
cd agripilot-ai
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
./.venv/bin/python -m streamlit run app.py
```

Then open http://localhost:8501. **No API keys are needed to run the app.** See below.

## Keys are optional

| Missing key | What happens |
|---|---|
| `OPENWEATHER_API_KEY` | Weather falls back to clearly-labelled demo data. Every page shows a banner saying so. |
| `LLM_API_KEY` | Explanations and next steps are generated by the calculation engine instead of the model. Every number is identical either way. |
| `LLM_API_KEY` (vision) | Crop-health image assessment reports itself as unavailable. It never guesses at a diagnosis. |

To add keys, copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml` and fill
it in. For Gemini, also uncomment `google-genai` in `requirements.txt`. In deployment,
set the same names as environment variables instead.

## Architecture

```
app.py                 Landing page, Streamlit entry point
pages/                 One file per screen, auto-discovered by Streamlit
ui/                    Theme, components, charts, the input form
agripilot/
  models.py            Dataclasses shared by everything
  catalog.py           Loads the JSON knowledge base
  pipeline.py          run_analysis(), the single entry point every page uses
  engine/              Deterministic calculations. No I/O, no LLM, no streamlit.
  services/            Weather, LLM, vision, PDF. Everything that can fail.
  db.py                SQLite persistence for recent analyses
  data/                crops.json, soils.json, regions.json, mock_weather.json
scripts/               Data validator and headless page render check
tests/                 65 tests, all offline
```

**The one rule that matters:** nothing in `agripilot/engine/` may import `streamlit`,
`requests` or an LLM SDK. Every number the user sees is calculated there, never by a
model (PRD §10, §17). The model only writes prose, and only from engine output.

The data flow is one direction:

```
farm + costs -> weather -> suitability -> water -> climate -> finance -> decision score
                                                                      -> AI explanation
```

## Development

```bash
./.venv/bin/python -m pytest tests -q          # unit tests, no network
./.venv/bin/python scripts/validate_data.py    # after editing agripilot/data/*.json
./.venv/bin/python scripts/smoke_pages.py      # render every page headlessly
./.venv/bin/python scripts/smoke_pages.py --empty   # ...with no analysis in session
```

`scripts/validate_data.py` is the contract with whoever owns the crop data: it checks
soil names, provinces, sowing windows, growth-stage totals, cost keys and coordinate
ranges, and flags crops whose typical revenue falls below their typical cost.

## Tuning the model without touching the plumbing

All scoring weights are module-level constants, deliberately grouped at the top of each
file under a `--- tunable constants ---` banner:

| What | Where |
|---|---|
| Suitability weights and penalties | `agripilot/engine/suitability.py` |
| Yield factor and water penalty | `agripilot/engine/finance.py` |
| Irrigation efficiency, supply factors, stress bands | `agripilot/engine/water.py` and `models.py` |
| Climate rule thresholds | `agripilot/engine/climate.py` |
| Decision-score weights and labels | `agripilot/engine/score.py` |
| Prompt wording | `agripilot/services/llm.py` |

## Deploying to Streamlit Community Cloud

1. Push to GitHub, connect the repo, set the entry point to `app.py` and Python to 3.12.
2. Add the secrets from `.streamlit/secrets.toml.example` in the Cloud dashboard.
3. Leave `packages.txt` absent. There are no apt dependencies, which is why the PDF
   uses reportlab tables rather than rendered chart images.
4. Smoke test the demo farm flow on the public URL from a phone.

## Data

Crop figures in `agripilot/data/crops.json` are indicative national-average planning
figures for Pakistan (2024-25 cost and price bands), not market quotes. They are marked
as such in the file's `_meta.source` and are meant to be corrected by whoever owns
agricultural data. The schema does not change when the numbers do.

## Disclaimer

AgriPilot AI provides AI-generated and model-based decision-support estimates. Results
may vary depending on actual field conditions, weather, soil conditions, crop varieties,
market prices, and other factors. Recommendations should be validated with local
agricultural experts and current field information before making major farming decisions.
